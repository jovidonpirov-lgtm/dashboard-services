# Статус — аналитика государственных услуг

Дашборд на русском языке: публичный просмотр текущих услуг, тарифов и истории; редактирование доступно одному администратору. Размещён на Vercel, код хранится в приватном репозитории.

## Возможности

- Раздел «Оплата услуг»: платные услуги первыми, минимальная и максимальная сумма тарифов, заполненность цен, фильтры и сценарий монетизации.
- Цена услуги: фиксированная или диапазон, в сомони либо показателях. Исходная ставка 78 с. задана пользователем и сохраняется отдельно с каждым тарифом; изменение ставки не пересчитывает старые отчёты. Цена может оставаться незаполненной.
- Суммы тарифов — стоимость одного обращения к каждой выбранной платной услуге с известной ценой. Сценарий умножает их на одинаковое число обращений и заданную долю дохода; это предположение, а не фактическая выручка. Незаполненные цены не заменяются нулями.
- Поле `pricing` добавлено без миграции имеющихся данных. Пропуск поля при сохранении из старой вкладки сохраняет прежний тариф, `null` явно очищает его. Новые цены сохраняются только в новом отчёте; конкурентные изменения защищены номером ревизии.

- Обзор текущих показателей, выполнение плана, динамика за 7/30/90 дней и произвольный период.
- Реестр услуг: уникальный ID, название, физические / юридические лица / обе аудитории, статус запуска. Поиск и фильтры.
- Один администратор, вход по паролю. Все изменения защищены серверной проверкой сессии; посетители видят те же актуальные данные и файлы без входа.
- Сохранение отчёта включает показатели, полный реестр, дату актуальности, время сохранения и комментарий. Старые отчёты не изменяются.
- История с просмотром каждого отчёта и сравнением произвольного периода.
- Демонстрационные цифры используются только в изолированной локальной проверке. При ошибке подключения рабочий сайт показывает ошибку загрузки, а не подставляет тестовые данные.
- Адаптивная версия для телефона и компьютера, клавиатурное управление диалогами, проверка введённых значений.

## Запуск локально

Требуется Node.js 22.13+ и pnpm 11.19.0.

```sh
corepack enable
pnpm install
node scripts/setup.mjs
pnpm dev
```

Откройте http://127.0.0.1:3000. Локальный пароль администратора находится в `local-access.txt`. Скрипт создаёт случайные пароль и ключ сессии в `.env.local`, не перезаписывая существующую конфигурацию. Оба файла исключены из Git.

Локально без `DATABASE_URL` реальные данные хранятся на сервере в `.data/dashboard.json`, атомарно, с проверкой версии. Это режим разработки для одного процесса. Для production необходим PostgreSQL; файловое хранилище в production запрещено.

## Размещение на Vercel

1. Импортировать приватный репозиторий `jovidonpirov-lgtm/dashboard-services` в Vercel. Framework: **Next.js**. Root directory: корень репозитория. Node.js: **22.x** или новее. Build: `pnpm build`.
2. Создать отдельный PostgreSQL в Railway, включить TCP Proxy для соединения из Vercel, создать отдельную базу и ограниченную роль приложения. Добавить серверные переменные окружения:

| Переменная       | Значение                                                                              |
| ---------------- | ------------------------------------------------------------------------------------- |
| `DATABASE_URL`   | Строка подключения к PostgreSQL, предпочтительно pooled URL с TLS (`sslmode=require`) |
| `ADMIN_PASSWORD` | Уникальный пароль, минимум 16 символов                                                |
| `SESSION_SECRET` | Случайный ключ, минимум 32 символа                                                    |

Ключ можно создать командой `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`.

3. Разделить базы Production и Preview, чтобы тестовые изменения не попадали в реальные отчёты. Не использовать префикс `NEXT_PUBLIC_` для секретов.
4. Запустить deployment. Таблицы `dashboard_state` и `dashboard_login_attempts` создаются автоматически при первом обращении; пользователю БД нужны права CREATE TABLE. Затем войти и сохранить первый реальный отчёт.
5. Настроить резервное копирование / point-in-time recovery на стороне PostgreSQL-провайдера. История отчётов не заменяет резервную копию базы.

Приложение не записывает данные на эфемерный диск Vercel. Без настроенной базы данные недоступны; без секретов вход и сохранение закрыты. Проект Vercel: `jovidon-s-projects/dashboard-services`. Сайт остаётся на Vercel; база размещена в отдельном проекте Railway `dashboard-services`:

- Railway: https://railway.com/project/4f018a3b-8cd4-4338-a286-7ee90c59dd2f
- Сервис PostgreSQL: `8715fc85-48d1-4adb-99f4-753331860ed5`.
- База: `dashboard_services`; роль: `dashboard_app` (без прав суперпользователя, создания ролей и баз).
- Внешнее соединение из Vercel через TCP Proxy, с `sslmode=require`. Шифрование и чтение/запись проверены.
- `DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET` сохранены в Vercel как Production secrets. Preview не имеет доступа к рабочей базе.
- Локальная резервная конфигурация соединения: `.env.railway.local` (права 0600, исключена из Git и загрузки в Vercel). Не подключайте её автоматически к локальной разработке, чтобы не изменять рабочие данные случайно.
- Ранее созданный Neon отключён от проекта; сам неиспользуемый ресурс Neon сохранён в аккаунте.

Рабочий адрес: https://dashboard-services-coral.vercel.app. Чтение данных публичное (200), запись без сессии администратора запрещена (401). Демонстрационные отчёты в рабочую базу не добавлялись.

Автопубликация из GitHub пока не подключена: Vercel возвращает ошибку о необходимости admin/write-доступа к `jovidonpirov-lgtm/dashboard-services`. Ручная публикация через `vercel deploy --prod --scope jovidon-s-projects` работает; блокировка автора устранена после настройки аккаунта владельцем.


## Как считаются показатели

- Вручную задаётся только «Заявлено». «На портале» = «Работают» + «Не работают», по реестру. Старый статус `portal` входит в неработающие без изменения самой записи. Запланированные услуги и услуги в разработке в сумму не входят.
- Физ, Юр и Физ/Юр — непересекающиеся группы. Каждая услуга учитывается один раз. Карточка оплаты показывает платные, бесплатные и незаполненные записи.
- Сохранённые отчёты сохраняют прежние значения портала. Обзор, график и сравнения используют расчёт по статусам на соответствующие даты без перезаписи истории.
- Работающих услуг не может быть больше заявленных; количество внесённых услуг каждой аудитории и статуса не должно противоречить итогам.
- Актуальность определяется датой последнего по календарю отчёта, а не датой открытия страницы. Часовой пояс: `Asia/Dushanbe` (UTC+5).
- Прирост за период **[начало, конец]** = последний отчёт на конец периода минус последний отчёт **до** начала периода. Если базового отчёта нет, показывается «Нет базы сравнения», а не выдуманный ноль.
- При нескольких отчётах за одну дату для сводки используется последняя сохранённая версия. В истории остаются все версии.
- Дни без отчётов на графике используют последнее известное значение. Это не подтверждение свежести данных; фактическая дата отчёта указана отдельно.
- Отчёт задним числом не заменяет актуальную сводку. Редактор первоначально копирует текущий реестр; администратор должен скорректировать его для исторической даты.
- Защита по revision предотвращает перезапись изменений из другой вкладки. При конфликте нужно обновить данные и повторить редактирование.

## Проверки

```sh
pnpm test
pnpm build
```

Интеграционная проверка требует отдельной пустой PostgreSQL-базы, которую можно безопасно удалить:

```sh
TEST_DATABASE_URL=postgres://... pnpm test:integration
```

Скрипт запускает production-сервер на `127.0.0.1:3107`, проверяет вход, серверную защиту, запись/чтение, исторические версии, конфликт одновременных записей и ограничения входа. Он очищает только таблицы в указанной тестовой базе, если её имя заканчивается на `_test`.

## Архитектура и ограничения

Next.js App Router, React, TypeScript, Zod, PostgreSQL. Сессия подписана HMAC, действует 12 часов, cookie HttpOnly / SameSite=Strict / Secure в production. Смена пароля или ключа аннулирует все сессии. Выход удаляет cookie браузера; индивидуального серверного отзыва ранее скопированной cookie нет. Изменяющие запросы проверяют Origin. Лимит входа общий для единственного администратора: 20 попыток за 15 минут, сохраняется в PostgreSQL.

Для начального небольшого реестра и одного администратора все версии хранятся одним JSONB-документом с атомарной проверкой revision. При существенном росте (тысячи услуг и длительная история) следует перенести снимки в отдельные строки и добавить пагинацию API. Максимальный размер одного отчёта — 2 МБ, до 10 000 записей реестра.

Шрифт Manrope загружается с Google Fonts; при недоступности применяется системный шрифт. Без регистрации и дополнительных пользователей.


## Вложения услуг

Документы доступны всем посетителям в `/files`, без входа. Администратор добавляет файлы в форме новой услуги или через скрепку в реестре. Поддерживаются PDF, DOC, DOCX, PNG, JPG; максимум 20 МБ на файл, 20 файлов на услугу, 1 ГБ всего. Вложения не меняют показатели отчётов.

Хранилище: Railway bucket `service-files`, регион `ams`, ID `63f8bfdc-6a69-4ebd-a712-50ecdaa9d035`. Секреты `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` заданы только для Vercel Production. Локальная защищённая копия — `.env.files.local`, исключена из Git и загрузки на Vercel.

Браузер загружает файл непосредственно в S3 по подписанному POST с ограничением размера, ключа и типа. Сервер проверяет размер и сигнатуру, затем копирует проверенный объект в отдельный неизменяемый ключ. Незавершённые объекты `staging/` удаляются правилом Railway через сутки. Метаданные находятся в `service_files`. Публичные ссылки выдаются только для завершённых файлов текущих услуг; удалённые из реестра услуги не показывают свои вложения. Удаление вложения через скрепку удаляет объект из хранилища. Прежние скачанные копии остаются у получателей.

При передаче `S3_*` в `pnpm test:integration` дополнительно проверяются реальная загрузка, CORS, публикация, скачивание без авторизации, совпадение байтов, удаление и неизменность отчётов. Тесты используют отдельную базу с суффиксом `_test` и удаляют тестовые файлы.
